# Blog Management System — API

A NestJS + Prisma (Supabase PostgreSQL) REST API for the Blog Management System programming test: registration with Super Admin activation, JWT auth (access + refresh), role-based blog CRUD with ownership rules, search, comments, and comment notifications with unread counts.

## Tech Stack

- NestJS 11 (TypeScript)
- Supabase PostgreSQL via Prisma ORM 7 (`prisma-client` generator, `@prisma/adapter-pg`)
- JWT auth (`@nestjs/jwt`, `passport-jwt`) with access + refresh tokens
- `class-validator` / `class-transformer` for request validation
- OpenAPI 3.0 generated by `@nestjs/swagger`, rendered with [Scalar](https://scalar.com/)

## Setup

1. Install dependencies:
   ```bash
   yarn install
   ```
2. Copy `.env.example` to `.env` and fill in real secrets.
3. Point the app at Supabase. In the Supabase dashboard go to **Project Settings > Database > Connection string** and copy both:
   - **Transaction pooler** (port `6543`) into `DATABASE_URL` — used at runtime.
   - **Direct connection** (port `5432`) into `DIRECT_URL` — used by `prisma migrate` / `prisma studio`, which cannot run through the pooler.

   Prefer offline development? A local Postgres is included — run `docker compose up -d` and set both URLs to
   `postgresql://postgres:password@localhost:5432/blog_db?sslmode=disable`.

   **TLS.** Supabase accepts unencrypted connections, so a connection string without an
   `sslmode` parameter connects in plaintext. The app never relies on that parameter: every
   connection goes through `src/prisma/pg-connection.ts`, which always enables TLS.
   Certificate *verification* needs Supabase's CA, because Supabase signs its own. That CA
   is committed at `certs/supabase-ca.crt` (`Supabase Root 2021 CA`, valid to 2031) and is
   picked up automatically; override the location with `PG_SSL_ROOT_CERT`. The CA is public
   information, not a secret. If the file is missing the API still connects — encrypted but
   unverified — and logs a warning at startup.
4. Apply the database schema:
   ```bash
   yarn prisma:migrate
   ```
5. Seed a Super Admin account:
   ```bash
   yarn prisma:seed
   ```
   Default credentials (override via `ADMIN_EMAIL` / `ADMIN_USERNAME` / `ADMIN_PASSWORD` env vars): `admin@blog.local` / `Admin@12345`.
6. Run the API:
   ```bash
   yarn dev
   ```
   The API is served under the `/api` prefix (e.g. `http://localhost:3001/api`).

## API documentation

The OpenAPI 3.0 spec is generated from the controllers and DTOs at startup — there is no
checked-in spec file to drift out of date.

| Route | What it is |
| --- | --- |
| `/api/reference` | **Scalar** — the primary reference UI, with a built-in request client |
| `/api/docs` | Swagger UI, kept as a fallback |
| `/api/openapi.json` | Raw spec, for client generators or importing into Postman/Insomnia |

Every operation carries a summary, a response schema with realistic examples, and the error
codes it can return. To try a protected route: `POST /auth/login`, copy `accessToken`, then
paste it into **Authentication** (Scalar) or **Authorize** (Swagger UI).

The `/api` prefix lives in the spec's `server` URL rather than in each path, so the curl
snippets Scalar generates are complete and copy-pasteable. That base URL defaults to
`http://localhost:<PORT>/api`; in production set `PUBLIC_API_URL` to the deployed URL,
including the `/api` suffix.

## Importing the legacy MySQL data

The project originally ran on MySQL. `prisma/migrate-from-mysql.ts` copies that data into
PostgreSQL, preserving primary keys (so foreign keys survive) and re-syncing the identity
sequences afterwards. Run it *after* step 4, with the old MySQL server reachable:

```bash
MYSQL_URL="mysql://root:password@localhost:3306/blog_db" yarn migrate:from-mysql
```

- `--dry-run` reports source and target row counts without writing.
- The script refuses to run when the target already holds rows; `--force` deletes them first.
- It verifies row counts per table at the end and exits non-zero on a mismatch.

Password hashes carry over unchanged, so existing accounts keep their passwords. Running
`yarn prisma:seed` is unnecessary when the import already brought over a Super Admin.

## Key Behavior

- New registrations start with `isActive: false` and `role: GENERAL_USER`; login is blocked until a Super Admin calls `PATCH /api/users/:id/activate`.
- Access tokens are short-lived (`JWT_ACCESS_EXPIRES`); refresh tokens are rotated and revoked on each use or logout (hashed with SHA-256 at rest, looked up by exact match — never hashed with bcrypt, since bcrypt truncates input at 72 bytes and these tokens are far longer).
- Blog `update` is restricted to the author; `delete` is allowed for the author or a `SUPER_ADMIN`.
- Posting a comment creates a `Notification` for the blog's author (skipped if commenting on your own post), with `GET /api/notifications` returning `unreadCount` alongside the list.
